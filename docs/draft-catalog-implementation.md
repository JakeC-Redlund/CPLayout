## Storage and Compatibility

**Web:** migrate to one versioned workspace envelope containing catalog, unchanged legacy project document strings and draft documents. Read and validate the latest envelope inside a named Web Lock, apply expected-revision checks, and commit the complete mutation with one `setItem`. All writers, including legacy rename/save/delete paths, must participate. If locking or storage is unavailable, retain editing/recovery export and report persistence unavailable. Do not claim a process-local promise queue protects multiple tabs.

The HTML storage standard does not provide cross-agent locking, and quota/security failure must be surfaced. The proposed named lock uses the Web Locks API, which is exposed in secure contexts; test actual target origins and two-tab behavior before acceptance. Both primary sources were refreshed on 2026-09-14. Web Locks remains a W3C Working Draft and is cooperative: unrelated old-version writers are not protected by a new lock name. This is an implementation decision inferred from these primary sources, not an assertion of runtime proof. [HTML storage](https://html.spec.whatwg.org/multipage/webstorage.html), [Web Locks](https://www.w3.org/TR/web-locks/).
