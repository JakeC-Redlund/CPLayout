# Final source and evidence arrangement

This is a preparation guide, not a completed proof packet. The workflow registry records the current source edition and its actual qualification. Preserve the zero-deletion retirement manifest and all preceding failures, interrupted runs and unavailable-source observations.

After code, fixtures, inventory, criteria, skills and generated routing context freeze, use the exported `wholeImplementationPaths(registry, root)` function in `tools/workflowStatus.cjs` to obtain the actual required implementation census. Build an immutable public `docs/evidence/…/*.json` source manifest with repository-relative `sourceHashes` and the SHA-256 of sorted compact JSON as `sourceFingerprint`. The manifest must cover every required census path. It must not hash itself, the registry or generated status: those are evidence/authority updates, not an implementation dependency. External skill symlinks, installed packages, private stores, served exports and runtime resources need their separately identified evidence.

Record the actual frozen aggregate commands and exit receipts. Bind the exported/served app bytes, browser fixtures, full discovered inventory, scope, concrete case results and viewport identities to that same implementation edition. Attach accessibility engine/version/tags, keyboard and focus results, PNG dimensions, DOM/bundle hashes and failed or incomplete findings. A focused selection, stale manifest, filename or routine passing log tail cannot substitute for the full required packet.

Every evidence entry needs its actual claim class/result, provenance, exact source commit/base plus frozen fingerprint, `edition`, `sourceManifest`, exact `sourceScope`, qualification boundary and the `requirementIds` it really assesses. A matching result is still limited to that claim class. Do not give source tests a browser, native, field, hook or deployment meaning. Preserve explicit supersession references to prior failures and close a defect only with its required recheck.

For final requirement promotion, use GOV-01/QA-01/PUBLISH-01's explicit implementation verification sources. QA-01 requires the complete implementation census in addition to its real code/inventory/criteria anchors; the registry and pause checkpoint remain authority/history references. Set its required claim class to the actual final browser result being assessed, with complete aggregate and two consecutive final independent reviews recorded separately. Source coverage is necessary, but it does not execute tests or prove reviews occurred.

Only after the matching final packet succeeds should independent reviewers assess the complete frozen edition. Record both actual accepted final reviews, their scope and findings without inventing human acceptance. Then record normal exact-head publication and protected CI independently. Hosted activation, deployment, device behavior and physical accuracy remain unproved until their own actual operational evidence is present.
