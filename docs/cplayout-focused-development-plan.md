## Non-Negotiable Boundaries

- Keep CPLayout free/no-cost and offline-first.
- Do not add Google Maps, paid Mapbox APIs, Esri paid services, paid imagery, cloud backends, hidden API keys, or trial-only SDKs.
- Keep canonical geometry as projected/local `XY` in the project CRS. WGS84, KML/KMZ, screenshots, CV masks, and operator labels are input, display, or evidence until accepted through projected-XY validation.
- Do not claim React Native directly runs Python, GDAL, RTKLIB, PyTorch, or companion ML/GIS packages.
- Keep Google Earth Pro, KML/KMZ styling, imagery, and local CV/ML outputs advisory unless geometry is explicitly imported through Files or edited on the Map with projected-XY validation.
- Do not claim native SQLite, ZIP sharing, native MapLibre, raw PMTiles/MBTiles, live GNSS, or on-device ML production readiness until the matching device/emulator proof passes. Android native SQLite and ZIP sharing require a current completed schema-v11 report; the 2026-06-05 schema-v10 SM-P613 report is historical artifact-specific evidence only. Android native MapLibre vector TileJSON/template rendering has historical SM-P613 report-specific evidence, not acceptance of the current build. iOS, raw PMTiles/MBTiles, imported local raster/aerial package rendering, live GNSS, and on-device ML remain proof-gated.

## Weighted-Vote Priority Order

The 2026-08-09 coordinator decision gives field acquisition correctness the highest product priority. The next development order is:

1. RTK receiver commissioning and field proof: connect a documented receiver through the implemented Web Serial lane, produce sanitized replay fixtures, validate correction/fix semantics, record antenna/reference-frame facts, occupy controls, and create the first hashed GNSS runtime report.
2. Android USB GNSS: build a local Expo native module/config plugin, prove permission/read/write/detach/reconnect on the target tablet and receiver, and keep all bytes behind the shared transport/session contract.
3. Correction delivery: keep receiver-managed NTRIP first; add an app client only after credential isolation, redaction, TLS/network failure, backpressure, and offline behavior are tested.
4. Native/runtime refresh: produce current Android schema-v11 SQLite/ZIP evidence, then repeat feature-specific MapLibre/raster and iOS gates. Hardware reports must match the current commit for release.
5. Real-world geometry/imagery validation: broaden operator-qualified fixtures, then address raw tile adapters and UI polish without weakening projected-XY or runtime-proof boundaries.
