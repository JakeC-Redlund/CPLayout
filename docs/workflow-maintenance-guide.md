# Workflow records and safe maintenance

[workflow-registry.json](workflow-registry.json) is the only current requirement/status ledger. [The master refocus](unified-workspace-refocus-2026-10-10.md) defines intent and acceptance; its architecture decision explains choices. Module contracts define behavior. Dated checkpoint/evidence files retain history rather than introduce another next-action queue.

For each bounded packet, record the requirement ID, source commit/fingerprint, owner, commands/results, evidence class, failed/partial attempts, residual gap and next action in the registry. A claim remains pending if its required proof is absent. Then run `node tools/workflowStatus.cjs --write` and `node tools/workflowStatus.cjs --check`; the projection is deterministic and preserves the complete archived preceding status bytes. Run the generator's tests when its contracts change. After indexed instructions/skills/docs freeze, the integration owner runs `npm run context-map:build`, `npm run context-map:check`, `npm run validate:skills` and `git diff --check`.

Verified requirements need passing current evidence that explicitly names the requirement in `requirementIds` and covers its declared verification source paths. The default verification scope is `sourcePaths`; explicit `verificationSourcePaths` must cover every declared implementation/proof-criteria path, excluding only the recognized `authorityReferencePaths`. Code cannot be reclassified as an authority reference. GOV-01, QA-01 and PUBLISH-01 exclude the mutable registry from their proof inputs; QA-01 also excludes the retained historical pause reference and requires complete candidate implementation coverage. See the [current acceptance protocol](workflow-acceptance-protocol.md). A dependency-graph comparison cannot qualify authentication, the interface or the whole workflow. Browser-debt migrations also require passing current scoped evidence naming the exact migrated case. Historical results remain historical.

The user delegates decisions; independent agent review replaces mandatory new questionnaires for this task. Historical human responses remain exact receipts. Never relabel synthetic review, generated figures or delegated approval as human acceptance. Hook scripts/context are advisory; configuration, source validation, discovery, execution, supported denial and managed installation are separately evidenced. Stop continuation stays disabled.

The current clarified intent is logical Customer → Project → Field folders, actual field design/Survey content and official Layout maps under their matched Survey. Record changes to that contract, the actual parent/source links, RTK qualification and retained-ancestor refusal in the same registry. Do not create a filesystem migration or copied document entities to implement presentation. A customer list must come from the authorized customer snapshot so empty customers survive. Record weighted judgments and user-intent/preservation vetoes separately from implemented behavior or measured acceptance.

After an intent or implementation change, retain old immutable manifests and packets as evidence for their original scope. The R7 full browser result and R8 bounded requalification remain foundations; earlier final-review work is intermediate for the clarified hierarchy. The old 902/915 censuses have verified coverage omissions, so preserve their actual lists and state that limitation rather than adding hashes retrospectively. The 955-path correction is census-tool proof only. Before current acceptance, rebuild the actual complete census with root fixtures, patches, public context-selected documents and validator inputs; record commands that ran separately from files merely inventoried.

## Retirement and deletion

Use [workflow-retirement-manifest.json](workflow-retirement-manifest.json). For each candidate inspect ownership and dirty/ignored work, inbound source/doc/skill/hook/test references, exact content hashes, historical provenance, replacement, held resource leases and recovery dependencies. Preserve an off-worktree recovery copy and verify restoration before deletion. Age, similar titles, duplicate bytes and irrelevance to one task do not qualify a file for deletion. Do not delete secrets or vendor source evidence by displaying their contents.

The current pass qualifies no source/evidence deletion. Keep the owner preference file, historical instruction archive, frozen readers, failed proofs, 960 deferred browser obligations, modeling packet and dirty/recovery worktrees. The three identical historical audit JSON files have distinct provenance and remain retained. Stale scheduling prose is superseded by links to the registry; archival moves need reference migration and original-byte hashes. Reproducible caches/build output may be considered only after the same ownership/reference/backup checks establish they are disposable.

Retention also applies to database ancestry. Future deletion must not remove customer/project/field placement while retained active or archived Survey evidence references it. Historical orphans remain readable/exportable with their parent unavailable; maintenance cannot guess replacement parents or rewrite old schemas. The registry retains the confirmed archive/delete-design → delete-project → delete-customer finding and its exact source/runtime rechecks.

Official-map maintenance must retain the V3 creation/finalization/reference metadata and immutable target/Survey links. Refuse bulk/raw restore of any V3 map without original service/workspace/account proof; preserve the input for recovery and use original reads/exports or the same-original-field dedicated reference import. A reference does not inherit official finalization, and cross-field import or V3→V2 writer downgrade cannot erase provenance. Keep original V1/V2 CRLF imports and all failed counterprobes. Record current receiver admission, wall-time tamper validation, actor attribution and actual field accuracy as separate proof boundaries.

Service whole-workspace recovery import must strictly advance the locked destination revision, after the existing V3 refusal gate. Equal or lower source revisions return `import_revision_conflict` without rewriting the input, stored bytes, revision, receipts or audit records. Keep the original file and reviewed hash; never manufacture a newer source revision to obtain admission. Normal administrator bootstrap creates V5 at revision 4, so a newly bootstrapped public workspace is not a revision-zero restore workaround. Legacy initial database insertion, reading and exact-source upgrade are separate compatibility paths. The [scoped correction receipt](evidence/production-workflow-review-20261011/cas-import-revision-correction-scoped-20261012.json) preserves the failed counterexample and actual stale-command, exact forward-import and concurrent-writer rechecks; current whole qualification remains in the registry.

Record full failed attempts and complete corrective reruns separately. A 267-pass/2-failure source packet remains failed even if its two files later pass their complete 114-case rerun. A helper's earlier five-pass receipt cannot replace its later six-case regression proof. Scope HTTP/PostgreSQL smoke separately from the served App: an old static export does not qualify current interface bytes. Preserve successful remote commits when stale client delivery retires; neither a refused callback nor a current receipt proves rollback or exactly-once UI behavior.

## Capability and dependency updates

The [skill inventory](skill-capability-inventory.md) records all exposed sources and applicability. Update an owned skill when a verified result changes its instructions; retain source date/hash and validation/runtime boundaries. Shared CV symlink owners and plugin cache sources are references, not permission to rewrite other repositories. Do not invent capability from package, skill, hook or model presence.

Use [dependency maintenance](dependency-maintenance.md) for daily reporting and weekly update groups. Keep raw advisories, installed patches, compatibility, browser/native proof and hosted activation separate. Source configuration does not prove a scheduler ran; compatible availability does not prove runtime support.
