# Current workflow acceptance protocol

The workflow registry is the authority for requirements, findings, evidence references and current status. Its generated status and historical pause checkpoint are references, not implementation proof inputs. Updating a status or evidence ID must not invalidate the implementation edition through a circular registry hash. Explicit `authorityReferencePaths` identify these narrowly recognized references; `verificationSourcePaths` must include every other declared source path.

Source scope is necessary evidence, not proof that a command executed or a journey passed. Final QA evidence must name QA-01, qualify its actual result class, cover the proof criteria and the complete current implementation/test/tool source scope, and retain the actual commands, results, source/bundle identities and reviewer findings. Narrow module evidence cannot qualify the whole application. The generator checks actual source bytes and rejects stale, unavailable, uncovered or unrelated-module evidence. Do not refresh hashes to hide drift: rerun the affected checks or provide a separately reviewed, bounded equivalence record.
